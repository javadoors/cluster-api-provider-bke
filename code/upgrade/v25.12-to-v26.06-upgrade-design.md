# 25.12 到 26.06 一键升级方案设计

## 1. 问题背景

### 1.1 版本特性

| 版本 | CVO 能力 | 升级机制 | 特殊说明 |
|------|---------|---------|---------|
| 25.12 | ❌ 无 | PhaseFlow | 已发布，无法修改代码 |
| 26.03 | ❌ 无 | PhaseFlow | 存在不兼容 CRD 变更 |
| 26.06 | ✅ 有 | CVO + ReleaseImage | 引入声明式升级框架 |

### 1.2 升级挑战

**核心矛盾**：
- 25.12 版本已发布，无法添加 CVO 能力
- 25.12 → 26.03 存在不兼容的 CRD 变更，需要预处理
- 需要一种机制让 25.12 能够升级到支持 CVO 的版本

**约束条件**：
1. 25.12 与 26.03 无 CVO 升级机制
2. 26.06 版本才新增 ReleaseImage 的 CVO 升级方案
3. 管理集群需要先升级到 CVO 方案（包括 InstallService 等组件）
4. 需要为 25.12 版本制作对应的 ReleaseImage
5. 使用新 CVO 把业务集群从 25.12 版本升级到 26.06 版本

### 1.3 设计目标

实现从 25.12 到 26.06 的**一键升级**，包括：
- 管理集群：25.12 → 26.06（通过 CVO）
- 业务集群：25.12 → 26.06（通过 CVO）
- 自动处理 25.12 → 26.03 的不兼容 CRD 变更
- 自动安装 CVO 框架
- 自动升级 InstallService 等核心组件

## 2. 升级路径设计

### 2.1 整体架构

```
└─────────────────────────────────────────────────────────────┘
                              │

┌─────────────────────────────────────────────────────────────┐

│  │  4. 升级 install-service                              │   │
```

### 2.2 升级流程

```
用户执行升级命令
    │
    ├── 1. 运行 bke-upgrade 工具
    │   └── bke-upgrade --cluster my-cluster --to 26.06
    │
    ├── 2. 工具检测当前版本 (25.12)
    │   ├── 连接管理集群
    │   ├── 读取 BKECluster CR
    │   └── 确认当前版本为 25.12
    │
    ├── 3. 安装 CVO 框架
    │   ├── 应用 CVO Deployment manifest
    │   ├── 等待 CVO 就绪
    │   └── 创建 ClusterVersion CR (current=25.12, desired=26.06)
    │
    ├── 4. CVO 接管升级流程
    │   ├── 加载 ReleaseImage (26.06)
    │   ├── 构建升级 DAG
    │   └── 按批次执行升级
    │
    ├── 5. 执行 pre-upgrade-migration
    │   ├── 检测版本范围 (25.12 → 26.03)
    │   ├── 执行迁移脚本
    │   └── 处理不兼容 CRD 变更
    │
    ├── 6. 升级核心组件
    │   ├── 升级 provider (bke-controller-manager)
    │   ├── 升级 install-service
    │   └── 升级到 26.06
    │
    └── 7. 完成升级
        ├── 更新 ClusterVersion.Status
        └── 输出升级结果
```

### 2.3 管理集群与业务集群升级顺序

**推荐顺序**：先管理集群，后业务集群

```
阶段 1：管理集群升级
    │
    ├── 1.1 安装 CVO 框架
    ├── 1.2 执行迁移 (25.12 → 26.03)
    ├── 1.3 升级 provider
    ├── 1.4 升级 install-service
    └── 1.5 升级到 26.06

阶段 2：业务集群升级
    │
    ├── 2.1 执行迁移 (25.12 → 26.03)
    ├── 2.2 升级 bkeagent
    ├── 2.3 升级 etcd
    ├── 2.4 升级 kubernetes-master
    └── 2.5 升级 kubernetes-worker
```

**理由**：
- 管理集群升级后，CVO 框架可用，可以管理业务集群升级
- 避免业务集群升级过程中管理集群不可用
- 降低升级风险

## 3. 独立升级工具设计

### 3.1 工具概述

**工具名称**：`bke-upgrade`

**功能**：
- 检测当前 BKE 版本
- 安装 CVO 框架（针对 25.12 等无 CVO 版本）

**使用方式**：
```bash
bke-upgrade --cluster <cluster-name> --namespace <namespace> --to <target-version>
```

### 3.3 核心实现

#### 3.3.1 版本检测

```go
package detector

type VersionDetector struct {
    client    client.Client
    cluster   *bkev1beta1.BKECluster
}

func (d *VersionDetector) DetectCurrentVersion(ctx context.Context) (string, error) {
    // 读取 BKECluster CR
    bkeCluster := &bkev1beta1.BKECluster{}
    if err := d.client.Get(ctx, types.NamespacedName{
        Name:      d.clusterName,
        Namespace: d.namespace,
    }, bkeCluster); err != nil {
        return "", err
    }
    
    // 返回当前版本
    return bkeCluster.Status.OpenFuyaoVersion, nil
}

func (d *VersionDetector) IsNonCVOVersion(version string) bool {
    nonCVOVersions := []string{"25.12", "26.03"}
    for _, v := range nonCVOVersions {
        if version == v {
            return true
        }
    }
    return false
}
```

#### 3.3.2 CVO 框架安装

```go
package installer

type CVOInstaller struct {
    client    client.Client
    manifests []string
}

func (i *CVOInstaller) Install(ctx context.Context) error {
    // 1. 安装 CVO 命名空间
    if err := i.applyManifest(ctx, "cvo/namespace.yaml"); err != nil {
        return err
    }
    
    // 2. 安装 ServiceAccount
    if err := i.applyManifest(ctx, "cvo/serviceaccount.yaml"); err != nil {
        return err
    }
    
    // 3. 安装 ClusterRole
    if err := i.applyManifest(ctx, "cvo/clusterrole.yaml"); err != nil {
        return err
    }
    
    // 4. 安装 Deployment
    if err := i.applyManifest(ctx, "cvo/deployment.yaml"); err != nil {
        return err
    }
    
    // 5. 等待 CVO 就绪
    return i.waitForCVOReady(ctx)
}

func (i *CVOInstaller) waitForCVOReady(ctx context.Context) error {
    return wait.PollImmediateUntil(
        5*time.Second,
        func() (bool, error) {
            deployment := &appsv1.Deployment{}
            if err := i.client.Get(ctx, types.NamespacedName{
                Name:      "cvo-controller",
                Namespace: "cvo-system",
            }, deployment); err != nil {
                return false, nil
            }
            return deployment.Status.ReadyReplicas == *deployment.Spec.Replicas, nil
        },
        ctx.Done(),
    )
}
```

#### 3.3.3 ClusterVersion 创建

```go
package bootstrapper

type ClusterVersionBootstrapper struct {
    client    client.Client
}

func (b *ClusterVersionBootstrapper) Bootstrap(
    ctx context.Context,
    bkeCluster *bkev1beta1.BKECluster,
    targetVersion string,
) error {
    currentVersion := bkeCluster.Status.OpenFuyaoVersion
    
    // 创建 ClusterVersion CR
    cv := &cvv1alpha1.ClusterVersion{
        ObjectMeta: metav1.ObjectMeta{
            Name:      bkeCluster.Name,
            Namespace: bkeCluster.Namespace,
        },
        Spec: cvv1alpha1.ClusterVersionSpec{
            DesiredVersion: targetVersion,
        },
        Status: cvv1alpha1.ClusterVersionStatus{
            CurrentVersion: currentVersion,
            Phase:          cvv1alpha1.ClusterVersionPhaseUpgrading,
        },
    }
    
    // 设置 OwnerReference
    if err := controllerutil.SetControllerReference(bkeCluster, cv, b.scheme); err != nil {
        return err
    }
    
    // 创建 CR
    if err := b.client.Create(ctx, cv); err != nil {
        if !apierrors.IsAlreadyExists(err) {
            return err
        }
    }
    
    return nil
}
```

#### 3.3.4 升级监控

```go
package monitor

type UpgradeMonitor struct {
    client    client.Client
}

func (m *UpgradeMonitor) Monitor(ctx context.Context, cv *cvv1alpha1.ClusterVersion) error {
    fmt.Printf("Monitoring upgrade progress...\n")
    
    return wait.PollImmediateUntil(
        10*time.Second,
        func() (bool, error) {
            // 读取最新的 ClusterVersion
            latest := &cvv1alpha1.ClusterVersion{}
            if err := m.client.Get(ctx, types.NamespacedName{
                Name:      cv.Name,
                Namespace: cv.Namespace,
            }, latest); err != nil {
                return false, err
            }
            
            // 输出进度
            m.printProgress(latest)
            
            // 检查是否完成
            return latest.Status.Phase == cvv1alpha1.ClusterVersionPhaseReady, nil
        },
        ctx.Done(),
    )
}

func (m *UpgradeMonitor) printProgress(cv *cvv1alpha1.ClusterVersion) {
    fmt.Printf("Current: %s -> Desired: %s\n", cv.Status.CurrentVersion, cv.Spec.DesiredVersion)
    fmt.Printf("Phase: %s\n", cv.Status.Phase)
    
    for _, condition := range cv.Status.Conditions {
        fmt.Printf("  - %s: %s\n", condition.Type, condition.Status)
    }
}
```

## 4. ReleaseImage 设计

### 4.1 管理集群 ReleaseImage

```yaml
apiVersion: v1alpha1
kind: ReleaseImage
metadata:
  name: bke-management-v26.06
  namespace: bke-system
  labels:
    cluster-type: management
    release-version: "26.06"
spec:
  version: "26.06"
  digest: "sha256:abc123..."
  
  upgrade:
    components:
      # Batch 1: 预创建资源
      - name: pre-upgrade-resources
        version: "26.06"
        inline:
          handler: EnsurePreUpgradeResources
      
      # Batch 2: 不兼容 CRD 迁移（25.12 → 26.03）
      - name: pre-upgrade-migration
        version: "26.06"
        inline:
          handler: EnsurePreUpgradeMigration
        dependencies:
          - name: pre-upgrade-resources
        migration:
          fromVersion: ">= 25.12 < 26.03"
          steps:
            - name: "migrate-crd-25.12-to-26.03"
              source:
                configMap:
                  name: migration-scripts
                  namespace: cluster-system
                  key: migrate-25.12-to-26.03.sh
              when: "crdExists('bkeclusters.v1beta1.bke.bocloud.com')"
              timeout: 5m
      
      # Batch 3: 自升级
      - name: provider
        version: "26.06"
        manifest: "provider/v26.06/component.yaml"
        dependencies:
          - name: pre-upgrade-migration
      
      - name: install-service
        version: "26.06"
        inline:
          handler: EnsureInstallServiceUpgrade
        dependencies:
          - name: provider
      
      - name: capi-controller-manager
        version: "26.06"
        manifest: "capi-controller-manager/v26.06/component.yaml"
        dependencies:
          - name: install-service
```

## 5. 迁移脚本设计

### 5.1 脚本位置

```
ConfigMap: migration-scripts
Namespace: cluster-system
Key: migrate-25.12-to-26.03.sh
```

### 5.2 脚本内容

```bash
#!/bin/bash
# migrate-25.12-to-26.03.sh
# 处理 25.12 到 26.03 的不兼容 CRD 变更

set -e

echo "Starting migration from 25.12 to 26.03..."

# 1. 备份现有 CRD
echo "Backing up existing CRDs..."
kubectl get crd bkeclusters.v1beta1.bke.bocloud.com -o yaml > /tmp/bkeclusters-backup.yaml
kubectl get crd bkenodes.v1beta1.bke.bocloud.com -o yaml > /tmp/bkenodes-backup.yaml

# 2. 迁移 BKECluster CRD
echo "Migrating BKECluster CRD..."
# 示例：字段重命名
kubectl get bkeclusters.v1beta1.bke.bocloud.com --all-namespaces -o json | \
  jq '.items[] | .spec.clusterConfig.cluster.openFuyaoVersion = .spec.clusterConfig.cluster.version | del(.spec.clusterConfig.cluster.version)' | \
  kubectl apply -f -

# 3. 迁移 BKENode CRD
echo "Migrating BKENode CRD..."
# 示例：类型变更
kubectl get bkenodes.v1beta1.bke.bocloud.com --all-namespaces -o json | \
  jq '.items[] | .status.stateCode = (.status.stateCode | tostring)' | \
  kubectl apply -f -

# 4. 更新 CRD 定义
echo "Updating CRD definitions..."
kubectl apply -f /tmp/bkeclusters-new.yaml
kubectl apply -f /tmp/bkenodes-new.yaml

# 5. 验证迁移结果
echo "Verifying migration..."
kubectl get bkeclusters.v1beta1.bke.bocloud.com --all-namespaces
kubectl get bkenodes.v1beta1.bke.bocloud.com --all-namespaces

echo "Migration completed successfully!"
```

## 7. 风险评估

### 7.1 风险识别

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| CVO 框架安装失败 | 升级中断 | 中 | 提供详细的错误日志，支持手动安装 |
| 迁移脚本执行失败 | 数据不一致 | 中 | 提供回滚机制，支持手动迁移 |
| install-service 升级失败 | 管理面不可用 | 中 | 添加回滚机制，支持手动恢复 |
| 版本检测错误 | 升级错误版本 | 低 | 添加版本校验逻辑 |
| ClusterVersion 创建失败 | 升级无法触发 | 低 | 添加重试机制 |

### 7.2 回滚方案

**场景 1：CVO 框架安装失败**
```bash
# 回滚 CVO 框架
kubectl delete -f cvo-install.yaml
# 重新运行升级工具
bke-upgrade --cluster my-cluster --to 26.06
```

**场景 2：迁移脚本执行失败**
```bash
# 恢复备份的 CRD
kubectl apply -f /tmp/bkeclusters-backup.yaml
kubectl apply -f /tmp/bkenodes-backup.yaml
```

**场景 3：install-service 升级失败**
```bash
# 回滚 install-service
kubectl rollout undo deployment/openfuyao-system-controller -n openfuyao-system-controller
```

本方案通过**独立升级工具 + CVO 框架**的组合，实现了从 25.12 到 26.06 的一键升级：
